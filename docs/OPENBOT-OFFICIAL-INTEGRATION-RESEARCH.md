# OpenMuse → OpenBot integration facts

Checked 2026-09-27 against [OpenBot `main` at `ca8d51c3`](https://github.com/CopilotKit/OpenBot/tree/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0), the [CopilotKit React Native reference](https://docs.copilotkit.ai/reference/react-native/components/CopilotKitProvider), and OpenMuse's [earlier integration boundary](OPENBOT-INTEGRATION.md). The OpenMuse **Available integrations** tile is an OpenMuse feature; the inspected upstream documents describe APIs and SDKs, not a one-click OpenMuse/OpenBot account-link flow.

## Native chat path

1. Ask authenticated OpenBot `GET /api/agents` for a Bot the actor may use. Create its conversation with `POST /api/channels` and `{ "agentIds": [botId] }`; the response contains the channel ID and its distinct Intelligence thread ID. `GET /api/channels` pages that actor's channels with `nextCursor`. OpenBot checks Bot visibility and channel membership server-side. [Agents route](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/server/src/agents/routes.ts#L384-L399), [channel create/list routes](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/server/src/channels/routes.ts#L1067-L1110), [channel creation](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/server/src/channels/routes.ts#L244-L307).
2. Point a separate React Native `CopilotKitProvider` subtree at the reachable OpenBot `/api/copilotkit` URL. Within it, `useAgent({ agentId: uniqueLocalId, runtimeAgentId: botId, threadId: channel.threadId })` binds the chosen Bot to that channel; send through `useCopilotKit().copilotkit.runAgent({ agent })`. This is the documented [React Native provider](https://docs.copilotkit.ai/reference/react-native/components/CopilotKitProvider), [thread-scoped agent](https://docs.copilotkit.ai/reference/react-native/hooks/useAgent), and [send pattern](https://docs.copilotkit.ai/react-native). OpenBot's own web app uses the same runtime URL and a channel-scoped agent. [Provider](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/app/src/lib/copilot/provider.tsx#L18-L39), [channel chat](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/app/src/components/channels/channel-chat.tsx#L240-L263).
3. Restore channel history through OpenBot's authenticated `GET /api/copilotkit/threads/:threadId/messages?agentId=:botId`, as its web client does. Do not depend on React Native `useThreads` for the OpenBot channel list: its reference explicitly says Intelligence thread management is currently **not usable on React Native**. [OpenBot history reader](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/app/src/lib/copilot/thread-messages.ts#L178-L201), [React Native `useThreads` limitation](https://docs.copilotkit.ai/reference/react-native/hooks/useThreads).

This supports real text chat with model-backed Bots and server-granted connector tools, subject to a live compatibility test. OpenBot's `/api/copilotkit` is its CopilotKit runtime, not the raw AG-UI endpoint expected by OpenMuse's `HttpAgent` mode. OpenBot constructs signed `forwardedProps.openbotRun` and `openbotDeploymentTools` **on its server** before calling remote Bots; the phone should not synthesize them. [Runtime mount](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/server/src/copilot.ts#L2205-L2271), [built-in server tools](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/server/src/copilot.ts#L320-L435), [remote Bot forwarding](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/server/src/copilot.ts#L1254-L1375).

## Capability and auth boundaries

- OpenBot's web provider mounts computer, skill, Bot-management, component, and approval hooks in the **web frontend**. A bare native provider does not register those tools, so it cannot honestly promise OpenBot computer/browser/file actions or their UI. Full capability needs equivalent native hooks and UI, or OpenBot's own web frontend. This is an inference from the [web provider registrations](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/app/src/lib/copilot/provider.tsx#L56-L78), [computer tool registrations](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/app/src/lib/copilot/computer-tools.tsx#L184-L255), and [server runtime construction](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/server/src/copilot.ts#L2205-L2271).
- Multiuser OpenBot uses a Better Auth session cookie (`credentials="include"` on its web provider); OpenMuse's workspace bearer is not an OpenBot login. OpenBot resolves the actor from the cookie for runs and thread ownership. `OPENBOT_SINGLE_USER=true` admits all reachable callers as one administrator; the documented supported scope is loopback or a private network such as a Tailnet, and every member of that network can act as admin. [Actor resolution](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/server/src/index.ts#L126-L178), [auth configuration](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/docs/configuration.md#L260-L297). A multiuser native session bridge is additional work; no documented OpenMuse-to-OpenBot OAuth exchange was found.
- Use a URL the physical Android phone can reach; its `localhost` is the phone unless `adb reverse` is active. Keep `INTELLIGENCE_API_KEY`, managed Bot tokens, and computer tokens on the server. [React Native device addresses](https://docs.copilotkit.ai/react-native), [OpenBot provider secret boundary](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/app/src/lib/copilot/provider.tsx#L18-L31).
- The checked OpenBot revision pins CopilotKit runtime/web client **1.73.1**, whereas this OpenMuse checkout pins React Native **1.70.1**. Align versions or verify run, reconnect, stop, and history against the deployed OpenBot before claiming native compatibility. [OpenBot runtime package](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/server/package.json#L21), [OpenBot web package](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/app/package.json#L21), [OpenMuse mobile package](../apps/mobile/package.json). The older [OpenMuse boundary note](OPENBOT-INTEGRATION.md) names OpenBot 1.70.1 and should not be treated as current-version evidence.

The correct near-term acceptance check is an authenticated channel create, a native text turn through OpenBot's CopilotKit runtime, and a history reload into the same OpenBot thread. A successful `/api/copilotkit/info` alone proves neither authorization nor a completed Bot run. [OpenBot actor resolution](https://github.com/CopilotKit/OpenBot/blob/ca8d51c3bf993e47e4d98a3c914a1958f1dafef0/server/src/index.ts#L136-L163).

## Local verification on September 27

The Android dev build listed the local OpenBot Bots and existing channels, created a General Assistant channel, and restored an older OMP channel's messages. The first new-channel turn failed while OpenBot's Intelligence client received an HTTP 502 during thread initialization. Retrying the **same channel** returned `OPENBOT_MUSE_OK` from General Assistant, and reopening it restored both the prompt and reply. This verifies channel creation, a live text run, and history reload across the deployed 1.73.1 runtime and the 1.70.1 native client. Stop behavior and frontend computer tools were not verified.
